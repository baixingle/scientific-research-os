# Research Memory Workflow

## Purpose

Research memory should preserve important decisions, reasoning, and evidence rather than raw conversation history.

It complements the researcher-facing `RESEARCH_STATE.md` rather than replacing it.

```text
RESEARCH_STATE.md  -> concise current scientific state
Decision records   -> important individual decisions
Research memory    -> durable continuity across the project
```

The state view should stay current and readable. Memory can preserve the historical context needed to understand how the project arrived there.

## What Belongs in Memory

Record information when losing it would cause repeated work, inconsistent interpretation, or loss of scientific context.

For each important decision, preserve:

## Decision

What was decided?

## Evidence

What observations or analysis support it?

## Alternatives Considered

What other explanations or paths were evaluated?

## Rejected or Deprioritized Options

Why were alternatives not selected?

## Confidence Level

How strong is the current conclusion?

## Next Trigger

What future result would change this decision?

## Relationship to the Research State View

After an important decision or accepted new result:

1. preserve the detailed decision or memory record when it has long-term value;
2. update `RESEARCH_STATE.md` with only the consequences that matter to the current project state;
3. link from the state view to detailed records instead of copying their full contents.

Do not turn `RESEARCH_STATE.md` into an ever-growing chronology.

## Principle

> Memory preserves why the project changed; the state view shows where the project is now.

A useful scientific record stores decisions and evidence, not conversation transcripts.
