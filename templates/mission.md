# Mission Template

## Mission ID


## Scientific Objective

What scientific uncertainty does this task address?


## Hypothesis or Comparison Tested

Which competing explanation, comparison, or decision does this task help distinguish?


## Context

Include only execution-relevant background.

Do not include unnecessary strategic discussion or a preferred scientific outcome.


## Inputs and Materials

Record only what is relevant to this task, for example:

- files, datasets, structures, models, or documents;
- samples, specimens, materials, reagents, or reference standards;
- protocol or method version;
- instrument, facility, software, or execution environment;
- controls, comparison groups, frozen definitions, or other required starting conditions.


## Allowed Operations

Clearly define what the executor may do.


## Forbidden Operations

Examples:

- changing scientific objectives;
- modifying acceptance criteria after seeing results;
- expanding scope without approval when the expansion is consequential;
- silently changing frozen methods, controls, analysis definitions, or experimental conditions.


## Required Outputs

Specify the outputs appropriate to the task, such as:

- files, measurements, raw data, processed data, samples, figures, or reports;
- run, experiment, instrument, or execution records;
- deviations, failures, anomalies, or unresolved issues;
- provenance and reproducibility metadata.


## Acceptance Criteria

How will completion be evaluated before the result is interpreted scientifically?


## Stop Conditions

When should the executor stop and report instead of continuing or adapting the task?


## Failure Interpretation

If the task fails or produces a null result, what scientific or operational information is gained?


## Reproducibility Information

Preserve whatever another competent researcher would need to understand, audit, and reasonably reproduce the important result.

Use only domain-relevant fields. Examples include:

**Experimental / wet-lab work, when relevant**
- sample or specimen IDs;
- reagent, material, vendor/catalog, batch, or lot information;
- protocol and protocol version;
- controls, replicates, randomization, or blinding;
- timing, temperature, atmosphere, preparation, or other critical conditions;
- instrument ID, settings, calibration, and acquisition method;
- operator or experimental batch when scientifically relevant;
- deviations from the planned protocol;
- raw-data location and sample-to-data mapping.

**Computational / simulation / ML work, when relevant**
- input structure or dataset version;
- code repository and commit/version;
- software and environment versions;
- parameters, model configuration, and data split definitions;
- random seeds;
- hardware or execution environment when it affects reproducibility;
- raw outputs, logs, checkpoints, and analysis scripts.

**Theoretical / analytical work, when relevant**
- assumptions and boundary conditions;
- definitions and conventions;
- derivation, notebook, or manuscript version;
- numerical approximations or external reference values that affect the result.

Do not require every field for every mission. Record information in proportion to scientific value and reproducibility risk.
